# Proposal: Coastal-Distance & Temporal Topic Analysis

## Goal

Run two complementary BERTopic analyses on the unified review corpus (`REVIEW_DATA`, 251 k rows, en + vi), then visualize how topic distributions shift:

1. **Across coastline-distance bands** — do beachfront hotels attract different feedback than inland ones?
2. **Across time (2018–2024)** — are topic proportions drifting year over year?

Both analyses share the same pre-computed embeddings already stored in `REVIEW_EMBEDDINGS`, so no re-encoding is needed. Each slice is fitted independently so its topic space is clean, and each fitted model is saved as a checkpoint.

After fitting, every topic is passed through an **LLM-assisted silver-label step** (Gemini) that converts raw BERTopic keyword clusters into structured aspect labels. These silver labels are the primary unit of analysis for the line-graph visualisations.

---

## Distance Bands

The `distance2coastline` column in `REVIEW_DATA` stores distance in **km**.  
Three bands capture the gradient from beachfront to clearly inland:

| Band | Label | SQL filter |
| --- | --- | --- |
| A | Beachfront (`< 0.1 km`) | `distance2coastline < 0.1` |
| B | Near-coast (`0.1 – 0.5 km`) | `distance2coastline >= 0.1 AND distance2coastline < 0.5` |
| C | Inland (`≥ 0.5 km`) | `distance2coastline >= 0.5` |

## Two New DuckDB Tables

Results are written back to `hotel_reviews.db` so they can be queried alongside `REVIEW_DATA`.

### `TOPIC_LABELS` — master topic registry per model run

Stores one row per (run_id, topic_id) with the full silver-label output.

```sql
CREATE TABLE TOPIC_LABELS (
    run_id            VARCHAR  NOT NULL,   -- e.g. "coast_band_A" or "year_2022"
    topic_id          INTEGER  NOT NULL,   -- BERTopic topic number (-1 = outlier)
    top_words         VARCHAR,            -- comma-joined representation keywords
    key_aspect        VARCHAR,            -- primary label from predefined taxonomy
    optional_aspects  VARCHAR,            -- JSON array of finer-grained sub-labels
    sentiment         VARCHAR,            -- "positive" | "negative" | "neutral"
    confidence        FLOAT,              -- LLM confidence score (0–1)
    evidence_keywords VARCHAR,            -- JSON array of supporting words
    short_reason      VARCHAR,            -- one-sentence justification
    n_docs            INTEGER,            -- size of topic cluster
    PRIMARY KEY (run_id, topic_id)
);
```

### `REVIEW_TOPICS` — per-review topic assignment

```sql
CREATE TABLE REVIEW_TOPICS (
    run_id     VARCHAR  NOT NULL,
    review_id  VARCHAR  NOT NULL,
    topic_id   INTEGER  NOT NULL,
    prob       FLOAT,
    PRIMARY KEY (run_id, review_id)
);
```

These two tables replace ad-hoc `.pkl` files and make the line-graph queries trivial SQL joins.

## LLM-Assisted Silver-Label Step

### Concept

After each BERTopic fit, each non-outlier topic is sent to **Gemini** together with:

- Its **top representation words** (`get_topic_info().Representation`, up to 10 words)
- A small set of **representative review documents** sampled from that topic cluster (up to 5 docs, ≤ 120 tokens each)

Gemini assigns:

| Field | Type | Description |
| --- | --- | --- |
| `key_aspect` | controlled | Single label from the predefined taxonomy |
| `optional_aspects` | free-form | Finer-grained sub-labels generated by the LLM |
| `sentiment` | controlled | `positive` / `negative` / `neutral` |
| `confidence` | float 0–1 | LLM self-reported confidence |
| `evidence_keywords` | list | Supporting words from the topic vocabulary |
| `short_reason` | string | One-sentence justification |

### Predefined `key_aspect` Taxonomy

Designed for Vietnamese seaside hotels. The LLM must pick exactly one:

| key_aspect | Covers |
| --- | --- |
| `location` | city-center access, surrounding area, transport, beach proximity |
| `room_comfort` | room size, bed, AC, décor, view from room |
| `cleanliness` | general cleanliness of rooms, bathrooms, and common areas |
| `service` | staff, reception, check-in/out, responsiveness |
| `food_drink` | restaurant, breakfast, buffet, bar, room service |
| `value` | price–quality ratio, cost, promotions |
| `facilities` | pool, gym, spa, parking, wifi, common spaces |

Topics that do not clearly map to any taxonomy entry receive `key_aspect = "other"`.

### `optional_aspects` Examples

These are generated freely by the LLM:

- `room_comfort` → `["room_design", "view", "bed_comfort", "air_conditioning"]`
- `food_drink` → `["breakfast", "buffet_quality", "restaurant_service"]`
- `beach_proximity` → `["sea_view", "private_beach", "beach_distance"]`
- `service` → `["staff_friendliness", "check_in_speed", "concierge"]`

### Expected JSON Output per Topic

```json
{
  "topic_id": 3,
  "key_aspect": "room_comfort",
  "optional_aspects": ["room_design", "view", "bed_comfort"],
  "sentiment": "positive",
  "confidence": 0.86,
  "evidence_keywords": ["phòng", "đẹp", "view", "rộng", "thoải mái"],
  "short_reason": "The topic mainly describes room appearance and comfort, with strong positive framing around space and sea view."
}
```

All labels — `key_aspect`, `optional_aspects` — are written in **English snake_case** regardless of whether the input reviews are Vietnamese or English.

### Gemini Labelling Code

```python
# src/llm_label.py

import json
import google.generativeai as genai

genai.configure(api_key=os.environ["GEMINI_API_KEY"])
model = genai.GenerativeModel("gemini-2.0-flash")

KEY_ASPECTS = [
    "room_comfort", "service", "cleanliness", "bathroom_hygiene",
    "location", "beach_proximity", "food_drink", "noise_control",
    "value", "facilities", "booking_refund", "parking_transport", "wifi",
]

def silver_label_topic(
    topic_id: int,
    top_words: list[str],
    sample_docs: list[str],
) -> dict:
    """Call Gemini to produce a silver label for one BERTopic topic."""
    docs_block = "\n".join(f"- {d[:120]}" for d in sample_docs[:5])
    prompt = f"""You are labelling hotel review topics for a Vietnamese coastal hotel study.

Allowed key_aspect values (pick exactly one):
{json.dumps(KEY_ASPECTS, ensure_ascii=False)}

Topic top words:
{", ".join(top_words)}

Representative review excerpts:
{docs_block}

Respond with JSON only — no markdown fences:
{{
  "topic_id": {topic_id},
  "key_aspect": "<one of the allowed values or 'other'>",
  "optional_aspects": ["<snake_case sub-label>", ...],
  "sentiment": "<positive|negative|neutral>",
  "confidence": <0.0–1.0>,
  "evidence_keywords": ["<word>", ...],
  "short_reason": "<one sentence>"
}}"""

    response = model.generate_content(prompt)
    return json.loads(response.text)


def label_all_topics(run_id: str, topic_model, docs: list[str], topics: list[int]) -> None:
    """Label every non-outlier topic and write results to TOPIC_LABELS."""
    info = topic_model.get_topic_info()
    info = info[info["Topic"] != -1]

    import duckdb
    con = duckdb.connect("hotel_reviews.db")

    for _, row in info.iterrows():
        tid       = int(row["Topic"])
        top_words = row["Representation"][:10]

        # Sample up to 5 representative documents for this topic
        idx       = [i for i, t in enumerate(topics) if t == tid][:5]
        sample    = [docs[i] for i in idx]

        label = silver_label_topic(tid, top_words, sample)

        con.execute("""
            INSERT OR REPLACE INTO TOPIC_LABELS
              (run_id, topic_id, top_words, key_aspect, optional_aspects,
               sentiment, confidence, evidence_keywords, short_reason, n_docs)
            VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
        """, [
            run_id, tid,
            ", ".join(top_words),
            label["key_aspect"],
            json.dumps(label["optional_aspects"], ensure_ascii=False),
            label["sentiment"],
            label["confidence"],
            json.dumps(label["evidence_keywords"], ensure_ascii=False),
            label["short_reason"],
            int(row["Count"]),
        ])

    con.close()
    print(f"[{run_id}] silver labels written — {len(info)} topics")
```

Topics with `confidence < 0.5` are flagged for manual review. `key_aspect = "other"` topics are excluded from the line-graph denominators but kept in `TOPIC_LABELS`.

## Pipeline — Analysis 1: Distance-Band Models

Produces **3 independent checkpoints**, one per band.

```text
run_id: "coast_band_A" | "coast_band_B" | "coast_band_C"
```

```python
# Pseudocode — src/run_coast_analysis.py

BANDS = {
    "coast_band_A": "r.distance2coastline < 0.1",
    "coast_band_B": "r.distance2coastline >= 0.1 AND r.distance2coastline < 0.5",
    "coast_band_C": "r.distance2coastline >= 0.5",
}

for run_id, where_clause in BANDS.items():
    ckpt = Path(f"checkpoints/{run_id}.pkl")
    if ckpt.exists():
        print(f"[{run_id}] checkpoint found — skipping fit")
        topic_model = BERTopic.load(str(ckpt))
    else:
        df, docs, embeddings = load_from_duckdb(extra_where=where_clause)
        topic_model = build_bertopic(min_cluster_size=30, min_topic_size=30)
        topics, probs = topic_model.fit_transform(docs, embeddings)
        topic_model.save(str(ckpt), serialization="pickle", save_ctfidf=True)
        _write_to_duckdb(run_id, df, topics, probs, topic_model)

    label_all_topics(run_id, topic_model, docs, topics)   # Gemini silver-label
```

## Visualisation — Line Graphs

Both charts use the same query pattern against `REVIEW_TOPICS` + `TOPIC_LABELS`, grouping by `key_aspect`.

### Chart 1 — Topic share over distance bands

X-axis: distance band (A → B → C).  
Y-axis: share of reviews assigned to each key_aspect (%).  
One line per key_aspect.

```sql
SELECT
    CASE
        WHEN r.distance2coastline < 0.1  THEN 'Beachfront'
        WHEN r.distance2coastline < 0.5  THEN 'Near-coast'
        ELSE 'Inland'
    END                            AS band,
    tl.key_aspect,
    COUNT(*)                       AS n_reviews,
    COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (
        PARTITION BY band
    )                              AS pct
FROM REVIEW_TOPICS rt
JOIN TOPIC_LABELS  tl ON rt.run_id = tl.run_id AND rt.topic_id = tl.topic_id
JOIN REVIEW_DATA   r  ON rt.review_id = r.review_id
WHERE rt.run_id LIKE 'coast_band_%'
  AND rt.topic_id != -1
  AND tl.key_aspect != 'other'
GROUP BY band, tl.key_aspect
ORDER BY band, tl.key_aspect;
```

### Chart 2 — Topic share over years (2018–2024)

X-axis: year.  
Y-axis: share of reviews per key_aspect (%).  
One line per key_aspect — allows you to see if "value" complaints rose post-COVID or "cleanliness" mentions spiked in a particular year.

```sql
SELECT
    CAST(REPLACE(rt.run_id, 'year_', '') AS INTEGER) AS year,
    tl.key_aspect,
    COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (
        PARTITION BY year
    )                              AS pct
FROM REVIEW_TOPICS rt
JOIN TOPIC_LABELS  tl ON rt.run_id = tl.run_id AND rt.topic_id = tl.topic_id
WHERE rt.run_id LIKE 'year_%'
  AND rt.topic_id != -1
  AND tl.key_aspect != 'other'
GROUP BY year, tl.key_aspect
ORDER BY year, tl.key_aspect;
```

Both charts are rendered in `notebooks/11_topic_coast_time.ipynb` using **matplotlib** (line graph with markers, one colour per key_aspect, shared legend).

## Checkpoint Strategy

```text
checkpoints/
├── coast_band_A.pkl     # BERTopic for d < 0.1 km
├── coast_band_B.pkl     # BERTopic for 0.1–0.5 km
├── coast_band_C.pkl     # BERTopic for d ≥ 0.5 km
├── year_2018.pkl
├── year_2019.pkl
├── …
└── year_2024.pkl
```

Checkpoint existence is checked at the start of each loop iteration — safe to kill and resume at any point. `REVIEW_TOPICS` uses `INSERT OR REPLACE` so re-runs don't duplicate rows.

## Risks & Mitigations

| Risk | Mitigation |
| --- | --- |
| Small band/year slices → noisy topics | Drop `min_cluster_size` to 20 for slices < 10 k rows; flag in chart annotation |
| Topic spaces differ per run — same concept lands on different BERTopic ID | Silver-label `key_aspect` normalises across runs; charts use key_aspect not raw topic_id |
| Gemini rate limits on 10 sequential model runs | Batch multiple topics per Gemini call (up to ~20 topics per request); fall back to per-topic calls |
| LLM assigns inconsistent `optional_aspects` spelling | Post-process: lower-case + replace spaces with `_`; flag duplicates in review |
| Low-confidence labels (`confidence < 0.5`) degrading analysis | Exclude from charts; store in TOPIC_LABELS for manual review |
| `distance2coastline` nulls | Filter `WHERE distance2coastline IS NOT NULL` in band queries |
| Checkpoint `.pkl` bloat (~50–200 MB each × 10 runs) | `checkpoints/` is gitignored; regenerable from `REVIEW_EMBEDDINGS` |
